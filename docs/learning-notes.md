记录项目中值得复习的问题、难点和高频考点。实际问题与知识整理分别标明；未执行的检查不能写成已通过。

## 01：非法输入校验——为什么输入框限制之外还要检查？

- 整理日期：2026-11-04
- 类型：第一阶段知识整理（基于现有实现，不代表新增发现的故障）
- 代码位置：`src/App.vue` 的 `addProject`、`saveEdit` 和名称输入框。

### 疑问与原因

输入框有内容，不一定是有效输入。例如 `"   "` 是非空字符串，但不能作为有意义的项目名称。名称输入框的 `maxlength` 可以限制正常输入，但业务函数仍应明确检查规则，避免只依赖界面限制。

### 当前处理

1. 用 `trim()` 去除名称、目标的首尾空白，保留目标中间的换行。
2. 用 `if (!name || !goal)` 拦截空字符串，并显示错误提示。
3. 检查名称长度是否超过 `projectNameMaxLength`（50）。
4. 校验失败立即 `return`，不执行后续新增或修改。
5. 全部通过后才更新项目数据；新增成功后清空表单，编辑成功后退出编辑状态。

```ts
const name = newProjectName.value.trim()
const goal = newProjectGoal.value.trim()

if (!name || !goal) {
  formError.value = '请填写项目名称和项目目标'
  return
}
```

编辑时先把原值复制到编辑表单，用户输入的是草稿；`saveEdit` 校验通过后才写回原项目。因此取消编辑或校验失败，不会把原项目改成无效内容。

### 验证与边界

- 根据开发路线中的 2026-11-03 验收记录：新增、编辑的空白输入均被拦截，编辑失败保留原数据；名称输入限制已由用户验证。
- 本次仅核对源码、整理笔记，未重新执行浏览器验收。
- 当前长度按 JavaScript 字符串的 UTF-16 代码单元计算，某些 emoji 会占两个或更多单位，并非严格按肉眼看到的字符计数。
- 前端校验帮助用户及时纠错；以后接入后端，服务端仍需校验，不能把前端检查当作数据安全保障。

复习时尝试解释：为什么先 `trim()`？为什么 `return` 必须放在修改数据之前？编辑表单为什么需要草稿？

## 02：本地存储——解析成功为什么仍不能直接使用？

- 整理日期：2026-11-04
- 类型：第一阶段知识整理与已有异常检查总结
- 代码位置：`src/App.vue` 的初始化读取、`Project`、`watch(projects, ...)`。

### 疑问与原因

`localStorage` 保存的是字符串。`JSON.parse` 只能判断字符串能否解析为 JSON，不能保证结果是合法项目数组。例如 `{}`、`[null]` 都是合法 JSON，却不符合业务结构。

TypeScript 的 `interface Project` 用于开发时的类型检查，不会自动在运行时检查浏览器存储中的数据。因此解析结果先声明为 `unknown`，检查后再使用。

### 当前处理

1. `getItem` 返回 `null` 表示没有保存数据，此时使用示例项目。
2. 有保存数据时，先解析，再检查是否为数组。
3. 检查每个元素：非空对象、id 为正安全整数、名称和目标为非空白字符串、状态属于允许值。
4. 使用 `Set` 比较 id 去重后的数量与数组长度，拒绝重复 id，避免列表标识和操作定位混乱。
5. 数据结构无效时显示提示并暂用示例项目；解析或读取抛错时由 `try/catch` 兜底。
6. 响应式项目数组变化后，通过 `watch` 序列化并保存；写入失败时提示“当前修改可能在刷新后丢失”，当前页面仍可继续操作。

### 关键区别：没有数据与空列表

`null` 代表尚无保存记录；`"[]"` 代表用户保存了一个空列表。用户删空项目后刷新，应继续显示空列表，不能恢复示例项目。当前实现只在读取值不为 `null` 时解析，合法空数组会被接受。

### 验证与边界

- 根据开发路线中的 2026-11-03 记录：隔离脚本检查过无保存数据、空数组、损坏 JSON、非数组、无效项目、重复 id、读取失败和保存失败。该检查模拟响应式接口，不等于完整浏览器交互测试。
- 用户已在浏览器确认删空后刷新仍为空，并且可以重新新增。
- 本次仅核对源码、整理笔记，未重新执行上述检查。
- 当前存储读取检查没有限制历史名称必须不超过 50，也没有对读取字符串再次去除首尾空白；不要把表单规则误写成所有数据入口都已统一执行。
- 使用示例项目属于界面降级，并不代表损坏数据已修复。后续修改触发保存时，会写入当前列表；目前没有损坏数据备份或恢复机制。
- localStorage 仅保存在当前浏览器的对应来源下，不提供账号隔离或跨设备同步。

复习时尝试解释：`unknown` 与直接断言为 `Project[]` 有何区别？JSON 合法为什么不代表业务合法？存储写入失败后页面为何还能操作？

## 03：数据编号、归属与默认数据

- 日期：2026-11-04
- 类型：用户提问整理；第二阶段数据关联基础
- 代码位置：`src/App.vue` 的 `Project`、`Issue`、初始化读取和示例问题数组。

`id` 是数据自身的稳定编号，不是数组下标或显示顺序。项目改名、排序后不需要改变 id。问题的 `id` 用于定位问题自身，`projectId` 则对应所属项目的 `id`；多个问题可以有同一个 `projectId`，但问题自身的 id 应各不相同。

项目列表优先使用 localStorage 中的合法数据，因此修改 `defaultProjects` 不一定改变页面；只有没有保存记录或当前实现遇到读取异常、格式错误时才使用示例项目。合法空数组仍保持为空。

示例问题写 `projectId: 1`，只表示它属于项目 1。如果项目 1 已被删除，按归属筛选时该问题不会出现在其他项目下；不需要恢复已删除项目。教学示例需要显示时，可以关联到一个现存项目。后续新增问题功能应自动使用当前操作项目的 id，用户无需手动管理编号。删除项目时如何处理关联问题，将在实现删除逻辑时明确。

2026-11-08 源码复核：当前 `issues` 已接入 localStorage 读写与结构校验；`deleteProject` 已清理关联问题及所属表单状态，尚待验收。按归属筛选后不可见不等于数据已删除；这里从数组末尾向前 `splice`，避免删除后元素前移导致漏删相邻问题。问题编辑归属检查在移除问题之前完成，以便仍能通过 projectId 判断归属。浏览器验收范围见开发路线，本次未新增浏览器验证。

## 04：`white-space: pre-wrap` 为什么能保留描述中的换行？

- 日期：2026-11-04
- 类型：用户提问；CSS 文本排版
- 代码位置：`src/App.vue` 的 `.issue-description`。

浏览器默认的 `white-space: normal` 会合并连续空格，并把文本里的普通换行当作空白处理，描述数据中有换行也不一定按原样显示。

`white-space: pre-wrap` 保留文本中的换行和连续空格，同时允许文字在容器宽度不足时自动换行。因此适合显示用户输入的多行问题描述。它与 HTML 的 `<pre>` 元素不同，这里只是给普通段落设置 CSS。

对比：`normal` 合并空白并自动换行；`pre` 保留空白但不按容器宽度自动折行；`pre-wrap` 保留空白且允许自动折行。特别长的连续字符仍需要配合 `overflow-wrap` 等规则处理，当前卡片段落已有 `overflow-wrap: anywhere`。

本次为知识说明与源码核对，未新增浏览器验证。

## 05：问题区域样式中的常见 CSS 面试考点

- 日期：2026-11-04
- 类型：结合当前页面整理的常见面试知识点；未统计具体公司的考题频率
- 代码位置：`src/App.vue` 的 `.issues-toolbar`、`.issue-title`、`.project-issues`、按钮状态和媒体查询。

1. **Flex 布局**：`justify-content` 控制主轴上的分布，`align-items` 控制交叉轴上的对齐；轴的方向取决于 `flex-direction`。当前工具栏使用默认横向主轴，标题和按钮两端对齐。`flex-wrap: wrap` 允许空间不足时换行。
2. **收缩与溢出**：`.issue-title` 的 `flex: 1 1 180px` 分别对应增长系数、收缩系数、基础尺寸；`min-width: 0` 允许 Flex 子项收缩到内容默认最小宽度以下，长字符串再配合 `overflow-wrap: anywhere` 断行。
3. **盒模型**：`content-box` 下声明的宽度不含 padding 和 border，`border-box` 下包含这两者。宽度为 100% 的输入框配合 padding 时，使用 `border-box` 可避免因此额外撑宽。margin 不属于这两种宽度计算的内部部分。
4. **选择器优先级与层叠**：`.project-card .issue-description` 比 `.project-card p` 优先级高，因此问题描述的 margin 能覆盖卡片普通段落的规则。只有在来源、重要性、层等条件相同时，才进一步比较选择器优先级；优先级相同且其他条件一致时，后声明的规则生效。
5. **交互伪类**：`:hover` 表示指针悬停，`:active` 表示元素被激活期间（如鼠标按住），`:focus-visible` 用于浏览器判断应显示焦点提示的场景，常见于键盘操作；不能只设计鼠标悬停而忽略键盘焦点。
6. **响应式布局**：当前 `@media (max-width: 480px)` 在视口不超过 480 CSS 像素时减少内边距；结合 Flex 换行和文本断行适配窄屏。媒体查询不是唯一手段，内容本身能伸缩也很重要。

视觉层级则通过项目标题字号、分组留白、问题区域背景和底部分隔线共同表达。它属于界面设计基础，不应把“边框圆角是多少”当作需要死记的考点。本次仅整理源码对应知识，构建通过不代表窄屏视觉效果已验证。

## 06：新增表单的打开、取消与重置流程

- 日期：2026-11-04
- 类型：用户指定记录；状态驱动界面与函数复用
- 对应设计：`startAddIssue`、`cancelAddIssue` 和 `addIssue`；方案已实现；2026-11-05 用户确认取消重开、保存后清空收起、空白校验与失败保留草稿通过浏览器验收。跨项目切换仅通过隔离函数测试。

表单是否出现由 `addingIssueProjectId` 决定；标题、描述和错误提示分别保存在三个 ref 中。`v-if` 收起表单只移除对应界面，不会自动清空这些定义在组件中的变量，因此需要主动重置。

流程：点击新增 → `startAddIssue(project)` → 调用 `cancelAddIssue()` 清理旧输入、错误和打开状态 → 设置当前项目 id → `v-if` 条件成立，显示空白表单。用户输入通过 `v-model` 写入变量。

点击取消 → `cancelAddIssue()` → 项目 id 设为 null，清空输入及错误 → 表单隐藏，不向问题数组添加数据。保存失败只设置错误并提前返回，保留用户输入供修改；保存成功先 push 新问题，再调用同一重置函数收起并清空表单。

复用同一重置函数，避免取消和保存成功的清理代码不一致。这里重置的是新增表单状态，不是删除问题数组中的记录。当前方案选择重新打开或切换项目时丢弃未提交草稿；不提供每个项目独立保存草稿的功能。

## 08：表单收起后页面整体位移

- 日期：2026-11-09；类型：实际问题。
- 现象：取消编辑时主框整体下移，仅增加淡出或关闭滚动锚定未解决。
- 原因：独立 Edge 采样中，表单收起令页面变短，scrollY 从约 1231 回调到 843，主框随之下移。此场景是滚动范围缩短，不能仅归因为草稿重置。
- 处理：条件表单使用网格高度和透明度过渡；收起时保留当前视口需要的最小页面高度，展开结束再更新，避免展开前清零造成二次跳动。
- 验证：首轮修改独立测试位移降至约 1px，随后补取整余量；用户确认取消与后续展开修正通过。保留项：底部可能有必要空白，完整窄屏与跨浏览器未验收。
